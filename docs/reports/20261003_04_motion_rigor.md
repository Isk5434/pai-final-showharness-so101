## 決めたこと（根拠つき）

- **作業姿勢 = 手先ピッチ 47°、手首ロール −90° 固定**
  - 真下向き（90°）は手首ピッチの可動域（±95°）に当たり、6方向に動ける点がバイアル周辺 3.6% / ラック周辺 0%。
    47° は 97% / 100%（`reachability.py`）。
  - 手首ロール −90° では、ピッチ・肘・手首ピッチの3関節が平行なので、どの姿勢でも指が水平に閉じる（数式どおり定数、テストで確認）。
    閉じ方向の「方位」を保つ方式は、腕が回ると閉じ方向が 13〜22° 傾き、固定指が下がって把持に失敗した。
- **回転トークンの意味**（5自由度で実現できる形）: RT_PITCH = アーム平面内で手先を ±10°、RT_YAW = 手を自分の軸まわりに ±10°（手首ロール、上から見て反時計回り = +）、RT_ROLL は常に拒否。
- **TCP = 固定指**: SO-101 は片側の指だけが動く。lerobot URDF の `gripper_frame` は固定指の面にあるので、物体中心は TCP から閉じ方向に「7 mm + 隙間 + 半径」ずれた位置に来る（`tcp_for_grasp`）。

## 詰まった点

| 症状 | 原因 | 解決 |
| --- | --- | --- |
| 真下向きで 2 cm 動かすと 0.8 mm 届かない | 手首ピッチが可動域の端 | 物理的制約と判明 → 作業姿勢を 47° に。解けないときは IK が誤差を「報告する」ことをテストで保証 |
| 動作中に最大 5.8 mm 行き過ぎ、ヨーが 5° 揺れる | 1ステップで最大 2 cm を指令し、低ゲインの関節が振れる。測定も静止を待っていなかった | 1ステップ 5 mm 上限 + 目標手前で減速 + 静止するまで待つ → 行き過ぎ 1.08 mm |
| Show-Harness 既定の「静止待ち」で行き過ぎが戻らない | 「計測位置から 0 移動」を指令するので目標が手と一緒に流れる | 常に目標（格子点）を保持する方式に作り直し |
| 回転中に手先が 5〜9 mm ずれる | 1ステップ 3.3° の回転は速すぎ | 0.5°/ステップ → 1.74〜2.75 mm |
| 1点で手先が 347 mm 暴走 | ラックに押し当たった反力を重力たわみとして学習し、指令がさらに押し込む正帰還 | 重力補正は小さい差だけ学習・上限つき。接触を検出したら即中断・その場で停止・報告 |
| 物理なしでは再現しない | 接触は sim 固有。再現テストに壁がなかった | 壁つきの物理なしアームを追加し、暴走しないことをテスト |
| 何も当たっていない遠い位置で「接触」と誤判定 | 腕を伸ばすと重力たわみ+遅れで関節差が閾値を超える | 「関節差が大きい」かつ「目標に進んでいない」ときだけ接触 |
| 把持で何も挟めていない（幅 0.3 mm） | TCP が固定指なのに、バイアル中心へ TCP を合わせていた | 片側グリッパー用の把持目標計算を追加 |
| 検証スクリプトが 22 万行に膨らんだ | 編集スクリプトが空文字列を置換した | git から復元、以後は置換箇所が1つだけかを assert してから編集 |
| `--grid_world "a|b|c"` で sim がハング | ラッパーが引数を引用せず、コンテナ内 bash が `|` をパイプと解釈 | `printf %q` で全引数を引用（引数なしの空文字も対策） |
| `pkill -f reachability` で自分のシェルが死ぬ | パターンが実行中のコマンド文字列にも一致 | pkill を使わず PID で止める |
| バウンディングボックスで「指がテーブルに 10 mm めり込む」と誤判断 | 箱は保守的すぎる | 実際の衝突形状（凸包頂点）を USD から抽出 → 最下点は TCP の 5.5 mm 下だけ |

## 追加で分かったこと（Phase 2 着手後）

| 症状 | 原因 | 解決 |
| --- | --- | --- |
| 把持がどの条件でも空振り（18/18 失敗） | バイアルのルート原点は中心ではなく円錐の先端寄り（41 mm ずれ）。先端の円錐をつまんで押し出していた | 局所外形から幾何中心を計算（14/18 成功に） |
| 指を 0.9 rad 開くと上から押し出す | 人のデモは 0.36〜0.46 rad しか開かない | 0.45 rad に |
| USD のワールド外形が乱択前の位置のまま | Fabric 有効時は USD が物理に追従しない | 寸法は局所外形、位置は物理の現在姿勢から |
| 空中で「接触」中断 | 接触を関節差から推定していた | sim に物理接触センサを追加し、どのリンクが何に何 N 当たったかを計測 |
| 隣のラックに手の甲が当たる | 片側グリッパーは挟む側で手の位置が変わる | 手首ロール ±90° のうち、衝突形状と障害物の隙間が大きい側を選ぶ |
| 大きなたわみで手が 278 mm 流れる | 実測関節から IK を解くと、補正しきれないたわみが毎ステップ積算する（ラック接触暴走と同じ仕組み） | 指令関節から解く方式に作り替え、残差は上限付き積分で閉じる |

## 改善点・次への宿題

- 床判定は今 TCP 1点だけ。衝突形状（`gripper_hull.json`）を使って「手全体がテーブルより上」に置き換える。
- 置き方（横倒しのバイアルを立ててラックへ挿す）には手先を約 90° 回す必要がある。RT_PITCH の実行可能範囲を把持状態で調べる。
