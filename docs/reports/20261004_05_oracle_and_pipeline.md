# レポート 05: 特権オラクルでのデータ収集と、学習までの一本道

日付: 2026-10-03〜04 / Phase 2（収集）＋ Phase 3（FT）の土台

## 何を実装したか

| ファイル | 内容 |
| --- | --- |
| `src/so101_showharness/oracle/vials_to_rack.py` | 特権オラクル。横倒しのバイアルを掴み、手先を前に倒して立て、ラックの空き穴へ落とす（人のテレオペデモと同じ流れ） |

| `scripts/train/export_rollouts.py`, `prepare_dataset.sh`, `rollouts_to_alpaca_rt.py` | 採用エピソード → Show-Harness の学習データ（プロンプト v5、回転トークン込み） |

## 人のデモから分かったこと（sreetz-nv/so101_teleop_vials_rack_left、3 エピソードを解析）

- 手首ロールは全期間 −90° 前後 → 「ロール −90° 固定」の設計と一致
- 把持: 手先ピッチ 56〜62°、TCP 高さ 41〜45 mm、指は 0.36〜0.46 rad しか開かない
- 離す: ピッチ −3〜−18°（手先ほぼ水平）、ラックの上 16〜20 cm から落とす

## 詰まった点

| 症状 | 原因 | 解決 |
| --- | --- | --- |
| 把持が全条件で空振り（18/18） | バイアルのルート原点が中心でなく円錐の先端寄り（41 mm）。先端をつまんで押し出していた | 局所外形から幾何中心を計算 → 14/18 成功 |
| 指を 0.9 rad 開くとバイアルを上から押し出す | 人は 0.36〜0.46 rad | 0.45 rad |
| ラック・バイアルの位置が古い | Fabric 有効時、USD のワールド外形は物理に追従しない | 物理の現在姿勢 + 局所外形 |
| 空中で「接触」 | 関節差からの推定。遠くで重力たわみ+遅れが閾値を超える | sim に物理接触センサ。推定は実機用の予備に |
| 大きなたわみで 278 mm 流れる | 実測関節から IK を解くと、補正しきれないたわみが毎ステップ積算 | 指令関節から解く方式に作り替え（動作検証 v6 で全項目合格） |
| 手の甲がラックに当たる | 片側グリッパーは挟む側で手の位置が変わる | 手首ロール ±90° のうち、衝突形状と障害物の隙間が大きく、かつ実行可能な側を選ぶ |
| ラックとの隙間が常に 0 mm | 回転したラックを軸平行の箱（AABB）で近似し、実物より大きく見ていた | ラックの座標系で向き付きの箱として判定 |
| 回転中に関節限界 | 回転する場所が悪い | 回転列が全部実行可能な近くの格子点（回転ステーション）を先に探して移る |
| 学習データから回転が消えた | Show-Harness の変換器が RT_* を黙って捨てる（実行時の履歴には入る） | 上流を変えずにラッパーで追加。上流への Issue 候補として `OSS_CONTRIBUTIONS.md` #12 に記録 |
| 学習環境: flash-attn が入らない | nvcc 無しでソースビルドに入る | 配布 wheel（`FLASH_ATTENTION_SKIP_CUDA_BUILD=TRUE`） |
| 学習が始まらない（deepspeed） | import 時に CUDA toolkit を要求 | 単 GPU では不要なので外した |
| 逆伝播で落ちる（tilelang） | tilelang も CUDA toolkit を要求。Hopper 向けの回避策 | `FLA_TILELANG=0`（L40S は Triton 経路） |
| 試験 7 を二重起動 | 起動直後でログが少なく、止まったと誤認 | 両方止めて掃除し、1 本で再実行。以後は `docker ps` で確認してから起動 |

## 改善点・次への宿題

- 残りの失敗（試験 7 の 4 件）: 離す直前に右へ動くとき、手に「バイアル・ラック以外の何か」から 2〜3 N の力 → マットとライトボックスを接触の内訳に足して原因を切り分け中。
- バイアル軸とアームの向きが 15° 以上ずれると立て切れない → RT_YAW（手のロール）で合わせる経路を追加する。
- 成功率 60% → 収集は採用分だけ使うので量産は可能。ただし失敗パターンが偏ると、学習データの配置にも偏りが出る（遠いバイアルが少ない等）→ 量産後に配置の分布を確認する。
- 次: 量産（目標 200 エピソード採用）→ 本番学習 → sim 閉ループ評価。
