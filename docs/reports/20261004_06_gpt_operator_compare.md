# 06 GPT オペレータ（サブスク Codex）と 3 モデル比較 v1

## 実装したこと
- `scripts/collect/gpt_operator_server.py`: ホスト側で `codex exec`（読み取り専用・一時セッション）を叩き、
  外部カメラ・手首カメラの 2 枚とプロンプトから 1 トークンを返す HTTP サーバ。
- `scripts/collect/gpt_collect.py`: sim 側の収集ループ。オラクルと同じ 3 形式（rollout / 30 Hz 軌道 / GUMI 動画）で記録し、
  「成功かつ途中中断なし」だけ採用。対象は真ん中のバイアル（vial_2）に固定。
- `scripts/collect/gpt_compare.sh`: 3 モデル（gpt-6-sol / gpt-5.6-terra / gpt-6-astra、effort low）を同じシードで比較。
  出力名を引数で変えられるようにした（v2 から）。

## 比較 v1 の結果（シード 3000, 3001、各 2 本）

| モデル | 成功 | 終わり方 | GPT 呼び出し | 拒否 | 平均応答 |
|---|---|---|---|---|---|
| gpt-6-sol | 0/2 | 2 本とも接触で中断 | 35, 34 | 1, 2 | 12.1〜12.6 s |
| gpt-5.6-terra | 0/2 | 接触で中断 / DONE と言ったが未配置 | 48, 65 | 11, 23 | 7.8〜8.0 s |
| gpt-6-astra | 0/2 | 上限切れ / DONE と言ったが未配置 | 70, 65 | 0, 0 | 9.4〜10.0 s |

サブスク使用量: 6 本・約 320 回の呼び出しで、週枠（7 日）の 0% → 4%。

## 詰まった点（根本原因）
- **6 本とも、一度もバイアルを掴めていなかった**（sim の `grasped` が全フレーム False）。
  - GRASP 時の手先の高さ: GPT は机上 3.5〜11 cm、オラクルは 1.2〜1.6 cm。高すぎて空振りしている。
  - 閉じた指の隙間: 掴めた時は約 29 mm、GPT の回はほぼ 0 mm。この固有感覚の情報を GPT に渡していなかった。
- GPT は掴めたと思い込み、その後「バイアルを立てる」つもりで `RT_PITCH_FWD` を連発した。
  その結果、関節限界で拒否されるか、ラック近くで回して接触し、中断していた。
- astra は GRASP / RELEASE を往復し続けた。手首カメラだけでは、掴めたかどうか判断できていない。
- terra と astra は、未配置なのに DONE と言った（見た目だけで判断して誤認している）。
- 当初のチャット報告では「掴んで持ち上げるまではできている」と書いたが、GPT の文章を鵜呑みにした誤りだった。
  数値ログ（grasped・指の隙間・GRASP 時の高さ）で確かめるべきだった。

## 改善（v2 プロンプト）
いずれも実機でも取れる固有感覚の情報だけで、シーンの正解位置などの特権情報は渡していない。
- 把持状態: `open` / `CLOSED and HOLDING (隙間 mm)` / `CLOSED ON NOTHING`。閾値は 15 mm で、実測の 29 mm と 0 mm の間。
- 手首の傾き: 指令ピッチと「離す姿勢（−20°）まであと何回 RT_PITCH_FWD か」。到達したら「これ以上回すな」と出す。
- 指先の机からの高さ（cm）と、掴む高さの目安（約 1.5 cm）。
- 手順の書き直し: 回すのはラックから離れて持ち上げた状態で行う。「完全に垂直にする必要はない」。
  DONE は RELEASE の後だけ。拒否された手は繰り返さない。
