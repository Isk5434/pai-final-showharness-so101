# レポート 03: SO-101 の IK とバックエンド（Show-Harness → Workshop sim 接続）

日付: 2026-10-03 / Phase 1（前半）→ **GO**

## 何を実装したか

| ファイル | 内容 |
| --- | --- |
| `scripts/sim/dump_kinematics.py` | sim の USD から関節チェーンを抜き出し、PhysX で 200 姿勢分の各リンク姿勢を取得 |
| `configs/so101_chain.json` | 抜き出した関節チェーン（sim と実機で共有する運動学モデル） |
| `src/so101_showharness/kinematics.py` | numpy の順運動学と IK（位置 + 手先ピッチ、減衰最小二乗 + 可動域の active set） |
| `src/so101_showharness/sim/workshop_backend.py` | Show-Harness の `AtomicSimEnv` 実装。手先 Δ → IK → 6関節目標 → env.step。重力によるたわみの補正、全 env.step を記録側へ渡すフック付き |
| `scripts/sim/probe_axes.py` | 各トークンの移動量・軸ずれ・所要ステップ・画像上の方向を実測 |
| `configs/primitives_so101.yaml`, `configs/robot_so101_sim.yaml` | 実測値と、制御・カメラの取り決め |
| `tests/` | 順運動学と PhysX の一致、IK の到達、トークン定義が Show-Harness と同じであることを確認 |

**結果**:
- 順運動学は PhysX と 0.1 mm 未満で一致した。
- 1 トークンの移動量は **19.96〜20.72 mm**（目標 20 mm）、軸からのずれは最大 0.93 mm、符号は 6 方向すべて正しかった。
- 停止中のずれは 0.6 mm。指を開いて閉じたときの幅は 81 mm → 1.5 mm だった。

## 詰まった点

| 症状 | 原因 | 解決 |
| --- | --- | --- |
| reset 姿勢から真上に 2 cm 動かすと 3 mm 届かない | reset 姿勢は手首ピッチが可動域上限まで 0.14 rad しかなく、上限で切られた分だけ IK の 1 ステップが無駄になって止まっていた | 上限に張り付いた関節を外して解き直す active set を追加 |
| URDF をそのまま使えるか分からない | 関節名とゼロ点が sim の USD と違う可能性があった | 推測で合わせず、sim の USD から直接チェーンを抜き出した（結果的に lerobot の SO-101 URDF と同じ値だった） |
| 外部カメラが動いて見えた | アームに隠れた部分を見間違えた（DR はすべて reset 時のみ） | 目視をやめ、手先をカメラ画像に投影して数値で方向を測るようにした |
| （設計）ゲインが低く、指令角と実際の角度がずれる | Pitch の剛性 30 などで、重力によるたわみが残る | 停止中に「指令 − 観測」を学習して指令に足す補正を入れた。指令と観測は記録でも別の列に保つ |

## 改善点・次への宿題

- 外部カメラの画像上では **MV_LEFT と MV_UP がどちらも「上」に見える**（斜め上から見下ろす配置のため）。
  FT では学習されるので問題になりにくいが、zero-shot の VLM プロンプトでは混乱しうる。手首カメラ側で区別させる。
  画像の回転は入れていない（回転させても曖昧さは消えないため）。**画像の回転は学習時の取り決めなので、Phase 2 の収集前に確定させる**。
- reset 姿勢は手首が可動域の端にあるので、収集・評価はまず 2〜3 トークン下げてから始めるのがよい。
- 指を空で閉じたときの幅は「Jaw 角度からの概算」。掴めたかどうかの判定は、Workshop の `vial_grasped`（接触センサ）を併用する。
- 次: 共通の軌道レコーダー（30 Hz、観測関節・指令関節・判断 ID）と、Show-Harness 形式 / LeRobot 形式への変換。
